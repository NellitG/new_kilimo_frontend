# Kilimo Stack frontend

A responsive React frontend foundation for Kilimo Stack, built with Vite.

## Run locally

Install dependencies with `npm install`, then run `npm run dev`. Use `npm run build` to create a production bundle. The agricultural hero photo and Google Fonts load from their public CDNs; the page uses system fallbacks if they are unavailable.

## Current scope

The React landing page is composed from reusable components in `src/components/`; shared service descriptions live in `src/data/services.js`. Service descriptions are informational and contain no records, user counts, permissions or production statistics. The sign-in form intentionally reports that authentication is not connected: the original Django project, endpoint contract, token handling and authorization rules were not present in the workspace, so no authentication behavior has been guessed.

The Agricultural Advisory card opens the Farmer Advisory AI chat at `/advisory`. To connect it to the existing backend, set `VITE_ADVISORY_CHAT_ENDPOINT` to the backend's chat endpoint. The frontend sends a credentialed `POST` with JSON `{ "message": "...", "messages": [{ "role": "user|assistant", "content": "..." }] }` and expects JSON containing a non-empty `answer`, `response`, or `message` string. The endpoint should apply the project's established authentication/CSRF policy and may use its existing advisory knowledge base/RAG service. No AI endpoint or contract was included in this frontend workspace, so the chat shows a configuration/service error rather than fabricated guidance until the backend URL is supplied. “Save chat” stores the current conversation in this browser's local storage; “Clear chat” clears the active conversation and that saved copy.

The OAN Network and Data Exchange service cards open the network workspace at `/oan-network`. Configure `VITE_OAN_DASHBOARD_ENDPOINT` with the existing authenticated backend dashboard/read endpoint. It should return JSON with an `overview` object (counts such as `participants`, `baps`, `bpps`, `activeConnections`, `transactions`, `domainSchemas`, `registryRecords`, and `transactionEvents`) and arrays named `participants`, `baps`, `bpps`, `schemas`, `registry`, `transactions`, `events`, and `monitoring`. The dashboard reads records and health values only from this response; omitted values remain unavailable and empty collections show an empty state. Detail panels can inspect returned records and event payloads. This repository contains no backend, OAN API contract, permission model, or Beckn integration, so registration/edit/activation, server-side filtering/pagination, real-time updates, and verified connectivity checks cannot be enabled or claimed until the corresponding backend capabilities are supplied.

The Knowledge & Resources and Farmer & Organization Services cards open the resource workspace at `/resources` and farmer workspace at `/farmers`. Configure `VITE_KNOWLEDGE_RESOURCES_API_URL`, `VITE_FARMERS_API_URL`, and `VITE_VALUE_CHAINS_API_URL` with the existing authenticated API collection URLs. Resource collection GET should return a JSON array (or `{results: []}` / `{items: []}`); POST accepts multipart metadata plus one or more `documents` files and returns created resource records. Resource detail URLs (`{collection}/{id}`) are used for PATCH and DELETE. Farmer collection GET returns profiles and POST accepts profile JSON (or multipart when a photo is attached); farmer detail URLs are used for PATCH and DELETE. The association action sends PUT `{valueChainIds: [...]}` to `{farmersCollection}/{farmerId}/value-chains`. Value chain GET returns a JSON array or paginated `results`/`items`. Backend authorization must enforce user roles and file policy; the frontend validates supported extensions and a 25 MB per-file limit. No farmer/resource APIs or backend permission rules were present in this repository, so the modules report disconnected states until the existing API URLs and compatible contracts are provided.

To connect the account flow, integrate the existing Django login endpoint and its established request, response, CSRF/token, redirect and error handling conventions. Add the existing route map and service APIs when those contracts are available.
